# Contributing to LucidOS

We appreciate your interest in contributing to LucidOS! This document provides guidelines and instructions for contributing.

## Code of Conduct

We are committed to providing a welcoming and inclusive environment. Please be respectful and constructive in all interactions.

## How to Contribute

### Reporting Bugs

- Use GitHub Issues to report bugs
- Describe the issue clearly and provide steps to reproduce
- Include system information and relevant logs

### Proposing Enhancements

- Create a GitHub Issue for feature requests
- Describe the proposed enhancement and use cases
- Be open to discussion and feedback

### Submitting Changes

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-feature`
3. Make your changes following our code style
4. Commit with clear messages: `git commit -m "Description of changes"`
5. Push to your fork: `git push origin feature/your-feature`
6. Create a Pull Request

## Code Style Guidelines

### Kotlin
- Follow the [Kotlin Coding Conventions](https://kotlinlang.org/docs/coding-conventions.html)
- Use meaningful variable and function names
- Keep functions small and focused
- Add documentation comments for public APIs

### General
- Maintain consistent indentation (4 spaces)
- Remove trailing whitespace
- Write clear, descriptive commit messages

## Pull Request Process

1. Ensure your code builds without errors
2. Add tests for new functionality
3. Update documentation as needed
4. Reference any related issues
5. Respond to review feedback promptly

## Development Setup

See [BUILD.md](docs/BUILD.md) for detailed setup instructions.

## Questions?

Feel free to open an issue or reach out to the maintainers.

Thank you for contributing to LucidOS!
